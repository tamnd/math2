## Example

Coins have the values $1$, $3$ and $4$, with as many coins of each value as we like.
The claim to test: "the [[greedy algorithm|PSM6NKYJB8]] pays each amount $m$ with the fewest coins".
The greedy algorithm is: while $m > 0$, take the largest coin $c \le m$ and replace $m$ by $m - c$.

1. Termination holds: each step decreases $m$ by at least $1$, and $m \ge 0$, so by the [[well-ordering principle|01BX15HSRR]] the procedure stops, with $m = 0$.
2. A weak correctness claim holds too: the coins taken always add up to the amount, by the invariant "(amount) $=$ (sum of coins taken) $+$ (current $m$)".
3. Now take $m = 6$. The largest coin $c \le 6$ is $4$, so the algorithm takes $4$ and leaves $2$.
4. The largest coin $c \le 2$ is $1$. The algorithm takes $1$, then $1$ again, and stops.
5. So the greedy payment is $6 = 4 + 1 + 1$, with $3$ coins.
6. But $6 = 3 + 3$ uses only $2$ coins.
7. So the greedy output is not optimal, and the claim is false.

The procedure stops and returns a valid payment, but it is not a [[proof by algorithm|~dc60f766]] of the optimality claim, because no invariant links each step to an optimal payment, and none can, since the claim fails.

## Remarks

1. The amount $6$ is the smallest failure for these coins. For $m \le 5$ the greedy payments $1$, $1 + 1$, $3$, $4$ and $4 + 1$ are optimal, which a check of all payments confirms.
2. More failures follow: for $m = 10$ the greedy payment is $4 + 4 + 1 + 1$, with $4$ coins, but $4 + 3 + 3$ uses $3$ coins.
3. For other coin systems greedy is optimal. With values $1$, $5$, $10$ and $25$, the greedy payment is optimal for each amount. A proof needs an argument about these specific values, not just a description of the procedure.
4. The example separates the two parts of a proof by algorithm. Termination and the weak invariant hold. The strong correctness claim, optimality, fails.
5. An algorithm that does find the fewest coins for each coin system exists: dynamic programming computes the least number of coins for $1, 2, \ldots, m$ in order. Its correctness proof is an induction on the amount.

## Explanations

### L1 human

Suppose that a shop has coins worth $1$, $3$ and $4$, and it must pay $6$.
A natural rule is to always take the biggest coin that still fits.
That rule gives $4$, then $1$, then $1$: three coins.
But two coins of $3$ also make $6$.
So "take the biggest coin" is a recipe that always ends and always pays the right amount, but it does not always use the fewest coins.

### L2 human

We find the fewest coins for each amount up to $7$, by dynamic programming, and compare with greedy.
Let $f(m)$ be the least number of coins for the amount $m$, with $f(0) = 0$ and $f(m) = 1 + \min \{ f(m - c) : c \in \{1, 3, 4\}, c \le m \}$.

1. $f(1) = 1$, $f(2) = 2$, $f(3) = 1$, $f(4) = 1$.
2. $f(5) = 1 + \min(f(4), f(2), f(1)) = 1 + 1 = 2$. Greedy: $4 + 1$, also $2$ coins.
3. $f(6) = 1 + \min(f(5), f(3), f(2)) = 1 + 1 = 2$. Greedy: $4 + 1 + 1$, with $3$ coins. Greedy fails here.
4. $f(7) = 1 + \min(f(6), f(4), f(3)) = 1 + 1 = 2$. Greedy: $4 + 3$, also $2$ coins.

The typical use of this non-example is to show that a procedure which stops and gives some answer is not yet a proof that the answer is the best one.
A trap is to test the greedy rule on a few small amounts, see that it works, and conclude that it always works.
