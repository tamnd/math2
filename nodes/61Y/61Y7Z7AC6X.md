## Example

Coins have the values $1$, $3$ and $4$, with as many coins of each value as we like.
The claim to test: "the [[greedy algorithm|PSM6NKYJB8]] pays each amount $m$ with the fewest coins".
The greedy algorithm is: while $m > 0$, take the largest coin $c \le m$ and replace $m$ by $m - c$.

1. Termination holds: each step lowers $m$ by at least $1$, and $m \ge 0$, so by the [[well-ordering principle|01BX15HSRR]] the procedure stops, with $m = 0$.
2. A weak correctness claim holds too: the coins taken add up to the amount, by the invariant "(amount) $=$ (sum of coins taken) $+$ (current $m$)".
3. Take $m = 6$: the largest coin $c \le 6$ is $4$, so the algorithm takes $4$ and leaves $2$.
4. The largest coin $c \le 2$ is $1$, so the algorithm takes $1$, then $1$ again, and stops.
5. The greedy payment is $6 = 4 + 1 + 1$, with $3$ coins, but $6 = 3 + 3$ uses only $2$.

So the claim is false.
The procedure stops and returns a valid payment, but it is not a [[proof by algorithm|X5HG1RNWQX]] of optimality: no invariant links each step to an optimal payment, and none can, since the claim fails.

## Remarks

The amount $6$ is the smallest failure for these coins.
For $m \le 5$ the greedy payments $1$, $1 + 1$, $3$, $4$ and $4 + 1$ are optimal, as a check of all payments confirms.
More failures follow: for $m = 10$ greedy pays $4 + 4 + 1 + 1$, with $4$ coins, while $4 + 3 + 3$ uses $3$.

For other coin systems greedy is optimal, for example with values $1$, $5$, $10$ and $25$.
A proof of that needs an argument about those specific values, not only a description of the procedure.
The example separates the two parts of a proof by algorithm: termination and the weak invariant hold, while the strong correctness claim fails.
Dynamic programming finds the fewest coins for every coin system, by computing the least number of coins for $1, 2, \ldots, m$ in order, and its correctness proof is an induction on the amount.

## Explanations

### L1 human

Suppose that a shop has coins worth $1$, $3$ and $4$, and it must pay $6$.
A natural rule is to always take the biggest coin that still fits.
That rule gives $4$, then $1$, then $1$: three coins.
But two coins of $3$ also make $6$.
So "take the biggest coin" is a recipe that always ends and always pays the right amount, but it does not always use the fewest coins.

### L2 human

We find the fewest coins for each amount up to $7$ by dynamic programming and compare with greedy.
Let $f(m)$ be the least number of coins for the amount $m$, with $f(0) = 0$ and $f(m) = 1 + \min \{ f(m - c) : c \in \{1, 3, 4\}, c \le m \}$.

1. $f(1) = 1$, $f(2) = 2$, $f(3) = 1$ and $f(4) = 1$.
2. $f(5) = 1 + \min(f(4), f(2), f(1)) = 2$, and greedy pays $4 + 1$, also $2$ coins.
3. $f(6) = 1 + \min(f(5), f(3), f(2)) = 2$, and greedy pays $4 + 1 + 1$, with $3$ coins, so greedy fails here.
4. $f(7) = 1 + \min(f(6), f(4), f(3)) = 2$, and greedy pays $4 + 3$, also $2$ coins.

A procedure which stops and gives some answer has not yet proved that the answer is the best one.
Watch out: a rule that works on the amounts $1$ to $5$ can still fail at $6$, so a few small tests prove nothing.
