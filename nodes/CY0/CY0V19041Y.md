## Statement

Consider the [[simply typed lambda calculus|2DP940895E]] with a base type $\mathsf{Bool}$, constants $\mathsf{true}, \mathsf{false} : \mathsf{Bool}$, and conditionals $\mathsf{if}\ t_1\ \mathsf{then}\ t_2\ \mathsf{else}\ t_3$ typed by the usual rule.
The values are $\mathsf{true}$, $\mathsf{false}$ and the abstractions $\lambda x{:}\tau.\, t$.
Let $\to$ be the call-by-value small-step [[operational semantics|N8SGDCGJTW]] on terms.

1. Progress: if $\vdash t : \tau$ with the empty context, then $t$ is a value or there is a term $t'$ with $t \to t'$.
2. Preservation: if $\Gamma \vdash t : \tau$ and $t \to t'$, then $\Gamma \vdash t' : \tau$.

Hence, if $\vdash t : \tau$ and $t \to^* t'$, then $t'$ is a value or can take a further step; a well-typed closed term never reaches a stuck state.

## Remarks

Progress is proved by induction on the typing derivation, using a canonical forms lemma.
The lemma says that a closed value of type $\mathsf{Bool}$ is $\mathsf{true}$ or $\mathsf{false}$, and a closed value of type $\sigma \to \tau$ is an abstraction.
Preservation is proved by induction on the derivation of $t \to t'$, and its key case is a substitution lemma: if $\Gamma, x : \sigma \vdash t : \tau$ and $\Gamma \vdash u : \sigma$, then $\Gamma \vdash t[u/x] : \tau$.
The term $\mathsf{if}\ (\lambda x{:}\mathsf{Bool}.\, x)\ \mathsf{then}\ \mathsf{true}\ \mathsf{else}\ \mathsf{false}$ is stuck: it is not a value and no rule applies.
The theorem predicts this, since the term has no type: the condition is a function, not a $\mathsf{Bool}$.
Progress needs the empty context: the open term $x$ with $x : \mathsf{Bool}$ is well typed, not a value and cannot step.

## Explanations

### L1 human

Type safety says that a program that passes the type checker cannot go wrong while it runs.
Each step of the computation keeps the type.
A typed program is never stuck in a state that has no meaning, such as using a function as a truth value.
Robin Milner put it as "well-typed programs cannot go wrong".

### L2 human

This syntactic form of type safety, split into progress and preservation, is due to Wright and Felleisen.
The same two lemmas are the standard way to prove safety of any [[type system|AVVQEG0MRJ]] given by an operational semantics.
Safety does not say that programs terminate: it also holds for languages with general recursion, where a safe program may run forever.
For the simply typed calculus, [[strong normalization|V2Z855MFPC]] adds termination on top of safety.
