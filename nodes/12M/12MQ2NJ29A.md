## Summary

Structural induction proves a fact about every object that is built by a fixed set of rules, such as lists, trees or formulas, by checking that each rule keeps the fact true.
Here is a theorem that it proves in a few lines: for all lists $xs$ and $ys$, the length of the joined list is the sum of the lengths,
$$\operatorname{len}(xs \mathbin{+\!\!+} ys) = \operatorname{len}(xs) + \operatorname{len}(ys).$$
A list is empty, or it is an element $a$ in front of a shorter list $xs$.
For the empty list both sides equal $\operatorname{len}(ys)$, and putting $a$ in front adds $1$ to both sides, so the equation survives each rule.
The [[length of a concatenation of lists|RZWGH0A048]] writes this proof out step by step.

In general, let $X$ be a set with an [[inductive definition|AM4GQQMZ3C]]: some base elements, some constructors that build new elements from old ones, and the clause that $X$ is the smallest set closed under them.
To prove $P(x)$ for every $x \in X$, a proof by structural induction has one case for each base element and one case for each constructor.
In a base case we prove $P(b)$ directly.
In the case of a constructor $c$ we assume $P(x_1), \dots, P(x_k)$ for the parts, the induction hypotheses, and prove $P(c(x_1, \dots, x_k))$.
Ordinary [[mathematical induction|0ASJVEFA9J]] is the special case of the natural numbers, built from $0$ by the successor.

## Motivation

Many objects in mathematics and computing are built in steps from smaller objects of the same kind.
An arithmetic expression is a variable, or two expressions joined by $+$ or $\cdot$ inside brackets.
A binary tree is empty, or a node with a left tree and a right tree.
To prove a claim about all such objects, we could give each object a size and use [[induction on size|B2D8PTFNN1]].
Structural induction skips the size and follows the definition itself, so the cases of the proof are the rules of the definition and nothing else.

This is the everyday proof method of computer science.
Every function that a program defines by recursion on a list or a tree has its properties proved by induction on the same list or tree.
In logic the same method proves facts about all formulas, and the [[induction on well-formed formulas|EDRV3N0SA3]] is its form there.
[[Inductive and recursive definitions|AM4GQQMZ3C]] describe the sets that the method works on.

## Notation

For binary trees we write $\varnothing$ for the empty tree and $\operatorname{node}(L, R)$ for the tree with left part $L$ and right part $R$.
The parts $L$ and $R$ are the immediate subterms of $\operatorname{node}(L, R)$, and a constructor with two parts gives two induction hypotheses.
For lists we write $[\,]$ for the empty list and $a :: xs$ for $a$ in front of $xs$.
Proofs say "by induction on $t$" or "by induction on the structure of $t$".

In Lean 4, a type of trees is declared as `inductive Tree | empty | node (l r : Tree)`, and Lean makes its recursor `Tree.rec` automatically, in the same way as `List.rec` and `Nat.rec`.
The tactic `induction t with | empty => ... | node l r ihl ihr => ...` opens one goal for each constructor, with the hypotheses `ihl` and `ihr` for the two subtrees.
For lists the cases are `nil` and `cons a as ih`.

## Remarks

### A first proof with brackets

Build arithmetic expressions by three rules: each variable is an expression, and if $e_1$ and $e_2$ are expressions, so are $(e_1 + e_2)$ and $(e_1 \cdot e_2)$.
We prove that every expression has as many left brackets as right brackets.
Let $\ell(e)$ and $r(e)$ be the two counts.
A variable has $\ell = r = 0$.
For the rule with $+$, the new expression has the brackets of $e_1$, the brackets of $e_2$, and one new pair:
$$\ell((e_1 + e_2)) = \ell(e_1) + \ell(e_2) + 1 = r(e_1) + r(e_2) + 1 = r((e_1 + e_2)).$$
The middle equality uses the two induction hypotheses, and the rule with $\cdot$ is the same calculation.
Check: $((x + y) \cdot z)$ has two left and two right brackets.

The proof has exactly three cases because the definition has exactly three rules.
The other examples follow the same pattern: [[a binary tree has one more empty subtree than nodes|V3FJMYC7Q1]] has one base case and one case with two hypotheses, and the [[length of a concatenation|RZWGH0A048]] has one base case and one case with one hypothesis.

### Why the method is valid

Let $X$ be the defined set, and let $T$ be the set of $x \in X$ with $P(x)$.
The base cases show that $T$ contains every base element.
The constructor cases show that $T$ is closed under every constructor.
The definition says that $X$ is the smallest set with these two properties, so $X \subseteq T$, and $P(x)$ holds for every $x \in X$.

So the whole weight rests on the word "smallest".
For the natural numbers, the base element is $0$ and the only constructor is the [[successor|0832XVR512]] $n \mapsto n + 1$.
The induction axiom of the [[Peano axioms|0QFT7Z76N5]] says exactly that $\mathbb{N}$ is the smallest set with these properties, and so ordinary induction is structural induction on $\mathbb{N}$.

### When to choose it

Choose structural induction when the objects come from an inductive definition and the claim is about functions defined by recursion on them.
Then each case of the proof can apply one rule of each definition, and the algebra usually writes itself.
Induct on the argument that the recursion takes apart.
Concatenation is defined by recursion on its first list, so the length theorem is proved by induction on $xs$, not on $ys$.

Every structural induction can be rewritten as a strong induction on size, because the immediate subterms of an element are smaller than the element.
Structural induction saves the step of choosing a size and proving that the parts are smaller.
When an argument must cut an object in a place that is not an immediate subterm, such as the middle of a list, induction on size is the better tool.

### What it is not

A correct base case and a correct step prove nothing about objects that the rules do not build.
The argument "$0$ is an integer, and if $x$ is an integer, then so is $x + 1$" has a true base case and a step that is true for every real $x$.
But the reals are not built from $0$ by adding $1$, so the argument says nothing about $\tfrac{1}{2}$, as [[induction on the reals by adding 1|TYRFKXSKTE]] shows.

A correct step also needs a correct base case.
The claim "every binary tree has an odd number of nodes" has a valid step: if $L$ and $R$ have odd numbers of nodes, then $\operatorname{node}(L, R)$ has $\text{odd} + \text{odd} + 1$ nodes, which is odd.
But $\varnothing$ has $0$ nodes, so the base case fails, and the tree $\operatorname{node}(\operatorname{node}(\varnothing, \varnothing), \varnothing)$ with $2$ nodes refutes the claim.

### Induction is easier than recursion

Induction over a set needs only the word "smallest", but definition by recursion over the same set needs more: each element must be built in only one way.
Let $X$ be the smallest set of numbers that contains $0$ and is closed under $x \mapsto x + 1$ and $x \mapsto x - 1$.
Then $X = \mathbb{Z}$, and induction over $X$ is valid: for example, it proves that every element of $X$ is even or odd.
Now try to define $f(0) = 0$ and $f(x \pm 1) = f(x) + 1$.
This gives $f(1) = 1$, and then, since $0 = 1 - 1$, also $f(0) = f(1) + 1 = 2$.
The number $0$ is built in two ways, and the two ways disagree, so this "definition" defines no function.
Lists and binary trees are safe, because each one is built in exactly one way.

### Watch out

The first common error is a missing case.
For formulas built with $\neg$, $\wedge$ and $\vee$, a proof with no case for $\neg$ is incomplete, even if the other cases are correct.

The second error is to use the hypothesis for an object that is not an immediate subterm.
In the case $a :: xs$ the hypothesis covers $xs$, and it does not cover the reverse of $xs$ or another list of the same length.
If you need such a list, switch to strong induction on the length.

The third error is to induct on the wrong variable.
For $\operatorname{len}(xs \mathbin{+\!\!+} ys)$, induction on $ys$ gets stuck, because no rule for $\mathbin{+\!\!+}$ applies to $xs \mathbin{+\!\!+} (b :: ys)$ while $xs$ is unknown.
More errors of this kind are in [[errors in induction proofs|V52HDTMPV5]].

### History

Rod Burstall made the method a standard tool for reasoning about programs in his paper "Proving properties of programs by structural induction", published in *The Computer Journal* in 1969.

### Try it

First, define $\operatorname{mirror}(\varnothing) = \varnothing$ and $\operatorname{mirror}(\operatorname{node}(L, R)) = \operatorname{node}(\operatorname{mirror}(R), \operatorname{mirror}(L))$, and prove that $\operatorname{mirror}(t)$ has as many nodes as $t$.
Both sides are $0$ for $\varnothing$, and for $\operatorname{node}(L, R)$ the two hypotheses give $n(\operatorname{mirror}(R)) + n(\operatorname{mirror}(L)) + 1 = n(R) + n(L) + 1$.

Second, with $\operatorname{rev}([\,]) = [\,]$ and $\operatorname{rev}(a :: xs) = \operatorname{rev}(xs) \mathbin{+\!\!+} [a]$, prove $\operatorname{len}(\operatorname{rev}(xs)) = \operatorname{len}(xs)$.
The base case is $0 = 0$, and the length theorem with the hypothesis gives $\operatorname{len}(\operatorname{rev}(xs) \mathbin{+\!\!+} [a]) = \operatorname{len}(xs) + 1 = \operatorname{len}(a :: xs)$.

## Explanations

### L1 human

Think of toys built from blocks by a few fixed rules.
To show that every toy has some property, check two things.
First, the single blocks have the property.
Second, each rule, applied to parts that have the property, gives a toy that has it.
Every toy is built from single blocks by the rules, so every toy has the property.
Counting $0, 1, 2, 3$ is the same idea with one block, $0$, and one rule, "add $1$".

### L2 human

Let us prove that a binary tree $t$ with $n(t)$ nodes and height $h(t)$ satisfies $n(t) \le 2^{h(t)} - 1$.
Both counts are defined by recursion on the tree:
$$n(\varnothing) = 0, \quad n(\operatorname{node}(L, R)) = n(L) + n(R) + 1, \qquad h(\varnothing) = 0, \quad h(\operatorname{node}(L, R)) = 1 + \max(h(L), h(R)).$$
For the empty tree, $n(\varnothing) = 0 = 2^0 - 1$, so the base case holds with equality.
For $\operatorname{node}(L, R)$ the hypotheses are $n(L) \le 2^{h(L)} - 1$ and $n(R) \le 2^{h(R)} - 1$.
Put $H = \max(h(L), h(R))$, so that both $2^{h(L)}$ and $2^{h(R)}$ are at most $2^H$, and add:
$$n(\operatorname{node}(L, R)) \le (2^H - 1) + (2^H - 1) + 1 = 2^{H + 1} - 1.$$
Since $h(\operatorname{node}(L, R)) = H + 1$, this is the claim for the new tree.
Check: $\operatorname{node}(\operatorname{node}(\varnothing, \varnothing), \operatorname{node}(\varnothing, \varnothing))$ has $3$ nodes and height $2$, and $3 = 2^2 - 1$.
The proof never numbered the trees, because the definition already supplied the cases.
That is the typical use: a claim about all values of a recursive data type, with one case for each constructor.

### L3 human

The defined set $X$ is the [[least fixed point|DBD64TH52D]] of the operator $F(Y) = B \cup C(Y)$, where $B$ is the set of base elements and $C(Y)$ is the set of elements that the constructors build from elements of $Y$.
Structural induction states that every set $T$ with $F(T) \subseteq T$ contains $X$, which is the defining property of a least fixed point.
In category theory, $X$ is the [[initial algebra|R76EC56V9R]] of a functor, and both structural induction and structural recursion come from its initiality.

The relation "$s$ is an immediate subterm of $t$" is a [[well-founded relation|0DQPNJNPYK]] on $X$, and structural induction is well-founded induction for that relation.
Proof assistants give each [[inductive type|Q80JWCWNKX]] its own induction principle, so lists, trees, formulas and the natural numbers are handled by one mechanism.
Other variants of induction in the same family are [[double induction|AABX4YPKRR]] and [[forward-backward induction|QC9FKGZH1V]].
