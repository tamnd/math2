## Definition

Let $\Pi$ be a maximization problem.
Each instance $x$ has a nonempty finite set of feasible solutions $y$, each with a value $v(x, y) \ge 0$.
Let $\mathrm{OPT}(x)$ be the largest value.
Let $\rho \ge 1$.
A *$\rho$-approximation algorithm* for $\Pi$ is a polynomial-time algorithm that outputs, on each instance $x$, a feasible $y$ with $v(x, y) \ge \mathrm{OPT}(x)/\rho$.
The problem $\Pi$ is *NP-hard to approximate within $\rho$* if the existence of a $\rho$-approximation algorithm for $\Pi$ implies $\mathrm{P} = \mathrm{NP}$.

For a minimization problem the condition on the output is $v(x, y) \le \rho \cdot \mathrm{OPT}(x)$, and the definition is otherwise the same.

## Remarks

Such results are usually proved through a *gap problem*.
For numbers $c > s > 0$, the gap problem asks to accept instances with $\mathrm{OPT}(x) \ge c$ and reject instances with $\mathrm{OPT}(x) < s$.
If this gap problem is [[NP|QQRA9GBW51]]-hard, then $\Pi$ is NP-hard to approximate within any $\rho < c/s$, since a $\rho$-approximation algorithm would separate the two cases.

Example: MAX-3SAT on formulas with exactly three distinct literals per clause, with the fraction of satisfied clauses as value, is NP-hard to approximate within $8/7 - \varepsilon$ for every $\varepsilon > 0$ (Håstad).
On the algorithmic side, a uniformly random assignment satisfies $7/8$ of the clauses in expectation, and this can be derandomized, so the ratio $8/7$ is achieved.

Non-example: the knapsack problem is NP-hard, yet it has a fully polynomial-time approximation scheme.
So for every $\rho > 1$ it has a $\rho$-approximation algorithm, and it is not NP-hard to approximate within any fixed $\rho > 1$ unless $\mathrm{P} = \mathrm{NP}$.

Hardness is also proved under other assumptions, such as the unique games conjecture or the exponential time hypothesis.
