## Definition

Let $I$ and $O$ be sets of finite objects, the inputs and the outputs, encoded as strings over a finite alphabet.
An *algorithm* from $I$ to $O$ is a finite description of a procedure with these properties:

1. at each stage the procedure performs one elementary step, which is uniquely determined by the description and the current data;
2. for each input $x \in I$ the procedure stops after finitely many steps;
3. when it stops on input $x$, it outputs an element $f(x) \in O$.

The algorithm then *computes* the function $f \colon I \to O$.
In a fixed [[model of computation|YFHEG4GYHW]] this is made exact: an algorithm is, for example, a [[Turing machine|758EYCN27B]] that halts on every input in $I$.

## Remarks

The informal clauses and the formal model are linked by the Church–Turing thesis, which is a thesis and not a theorem.
It says that every function computable by an informal algorithm is computable by a Turing machine.
Many texts drop clause 2 and call a procedure that may run forever a partial algorithm or a semi-algorithm.
Randomized and nondeterministic algorithms relax clause 1.

Example: the [[Euclidean algorithm|0TRNT4X7J0]] is an algorithm from pairs of natural numbers to natural numbers.
Each step replaces $(a, b)$ by $(b, a \bmod b)$, the second entry strictly decreases while it is positive, so the procedure stops, and it outputs $\gcd(a, b)$.

Non-example: "search the natural numbers $n = 1, 2, 3, \dots$ for an odd perfect number and output the first one found" is a precise procedure.
But nobody knows whether it stops, so it is not known to satisfy clause 2.
