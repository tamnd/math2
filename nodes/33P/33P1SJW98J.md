## Example

Problem: with a jug of exactly $4$ litres, a jug of exactly $6$ litres and unlimited water, get exactly $5$ litres in one jug.
The moves are as in [[the jug problem with 4 and 9 litres|CJJZX90P2M]]: fill a jug, empty a jug, or pour from one jug into the other until the first is empty or the second is full.
A state is a pair $(s, \ell)$ of amounts in the small and the large jug, and the start is $(0, 0)$.

We try [[working backwards|3QTB9S1THS]] and see where it misleads.

1. Goal: $\ell = 5$. A full large jug holds $6 = 5 + 1$ litres, so we could pour $1$ litre out of a full large jug.
2. A pour moves exactly $1$ litre into the small jug when the small jug holds $3$ litres. New goal: $s = 3$.
3. To get $s = 3$, we could pour $3$ litres from the large jug into an empty small jug, but the pour stops at $4$ litres or when the large jug is empty. So the large jug must hold $3$ litres. New goal: $\ell = 3$.
4. To get $\ell = 3$, we could pour $3$ litres out of a full large jug, so the small jug must hold $1$ litre. New goal: $s = 1$.
5. To get $s = 1$, either the large jug holds $1$ litre and is poured into the empty small jug, or a full small jug pours $3$ litres into a large jug that holds $3$ litres. Each new goal asks again for an odd amount.

The backward chain moves between the goals "$1$ litre", "$3$ litres" and "$5$ litres", and none of these goals is the start $(0, 0)$.
Working backwards gives no plan, but it also gives no proof that a plan does not exist: perhaps a cleverer backward step was missed.

An [[invariant|8NQ190278Y]] settles the question.

1. Claim: in every state that can be reached from $(0, 0)$, both amounts are even.
2. The start $(0, 0)$ has both amounts even.
3. Filling a jug gives $4$ or $6$ litres in it, which is even. Emptying a jug gives $0$, which is even.
4. A pour from one jug into the other moves either all the water of the first jug or the free space of the second jug. The free space is $4 - s$ or $6 - \ell$. If $s$ and $\ell$ are even, each of these amounts is even.
5. So each move keeps both amounts even, and by induction on the number of moves the claim holds.
6. The goal needs $5$ litres in a jug, and $5$ is odd. So no sequence of moves reaches the goal.

## Remarks

The non-example shows a limit of working backwards: it can find a plan, but the failure to find one proves nothing.
To prove that a goal cannot be reached, we need an argument about all states at once, such as a [[parity argument|H9JT1XNDKQ]].

The invariant also explains the backward chain: read backwards, each move from a state with an odd amount comes from a state with an odd amount.
A computer search over all $5 \cdot 7 = 35$ pairs $(s, \ell)$ confirms that only $10$ pairs can be reached, and that each of them has both amounts even.

The general rule: with jugs of $p$ and $q$ litres, the amounts that can be reached are the multiples of $\gcd(p, q)$ up to the size of the large jug.
For $p = 4$ and $q = 6$ we have $\gcd(4, 6) = 2$, so the amounts are $0$, $2$, $4$ and $6$.

## Explanations

### L1 human

Both jugs hold an even number of litres when full.
If we only fill, empty and pour, every amount stays even.
So we can never see $5$ litres, which is odd.
Working backwards from $5$ kept asking for $1$ or $3$ litres, and it never got anywhere.
But that alone did not prove anything; the even-number argument did.

### L2 human

We compare the two ways to treat an impossible goal.

1. A backward search from the goal can only list the states that lead to it. If it runs out of new states, a complete search proves impossibility, but a search by hand is seldom complete.
2. An invariant is one property, here "both amounts are even", that holds at the start, is kept by each move, and fails at the goal.
3. For the goal $\ell = 5$, the invariant fails at the goal since $5$ is odd. So the goal is unreachable.
4. For jugs of $6$ and $9$ litres and the goal of $4$ litres, the invariant "both amounts are multiples of $3$" works in the same way.

The typical use: when working backwards keeps returning to the same kind of goal, look for a quantity that every move preserves.

A trap: a short backward search that fails is not a proof; a missed move could open a path.
