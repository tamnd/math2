## Problem

Let $s_1, \dots, s_n$ be item sizes with $0 < s_i \le 1$.
A *packing* into $k$ bins is a partition of $\set{1, \dots, n}$ into $k$ sets $B_1, \dots, B_k$ with $\sum_{i \in B_j} s_i \le 1$ for each $j$.
The *bin packing problem* asks for a packing that uses the least number of bins $k$.
In the decision version, an integer $k$ is given, and the question is whether a packing into $k$ bins exists.

## Remarks

The decision version is NP-complete, and the optimization version is [[NP-hard|MHA48AWBXN]].
Already the case $k = 2$ is hard, because it contains the partition problem.
The same reduction shows that no polynomial-time algorithm achieves an [[approximation|4WEVBDQ8SR]] ratio better than $3/2$ unless $\mathrm{P} = \mathrm{NP}$.
The first fit rule puts each item into the first open bin where it fits and opens a new bin otherwise.
It never uses more than $2 \cdot \mathrm{OPT}$ bins, since at most one bin can be at most half full.
Sorting the items in decreasing order of size before first fit gives the first fit decreasing rule, which uses at most $\frac{11}{9} \mathrm{OPT} + 1$ bins.
The total size $\sum_i s_i$, rounded up, is a lower bound for the optimum.

## Explanations

### L1 human

You have boxes of the same size and a pile of objects of different sizes.
The question is how few boxes are enough to hold all the objects.
For example, items of sizes $0.6, 0.5, 0.4, 0.5$ fit into two bins: $\set{0.6, 0.4}$ and $\set{0.5, 0.5}$.
Simple rules, like putting each object into the first box where it fits, work well in practice.
Finding the true minimum is hard in general.
