## Example

The TBox $\mathcal{T}$ contains two definitions.

$$
\mathsf{Parent} \equiv \mathsf{Person} \sqcap \exists \mathsf{hasChild}.\mathsf{Person}, \qquad \mathsf{Mother} \equiv \mathsf{Parent} \sqcap \mathsf{Female}
$$

The ABox $\mathcal{A}$ contains four assertions.

$$
\mathsf{Person}(\mathsf{mary}),\ \mathsf{Female}(\mathsf{mary}),\ \mathsf{hasChild}(\mathsf{mary}, \mathsf{tom}),\ \mathsf{Person}(\mathsf{tom})
$$

We check three questions about the [[description logic|TXQ80B8ZSA]] knowledge base $\mathcal{K} = (\mathcal{T}, \mathcal{A})$.

1. In any model $\mathcal{I}$ of $\mathcal{K}$, $\mathsf{tom}^{\mathcal{I}}$ is a person and a $\mathsf{hasChild}$-successor of $\mathsf{mary}^{\mathcal{I}}$.
   So $\mathsf{mary}^{\mathcal{I}} \in (\exists \mathsf{hasChild}.\mathsf{Person})^{\mathcal{I}}$.
2. With $\mathsf{Person}(\mathsf{mary})$, the first definition gives $\mathsf{Parent}(\mathsf{mary})$, and with $\mathsf{Female}(\mathsf{mary})$ the second gives $\mathsf{Mother}(\mathsf{mary})$.
   So $\mathcal{K} \models \mathsf{Mother}(\mathsf{mary})$.
3. $\mathcal{T} \models \mathsf{Mother} \sqsubseteq \exists \mathsf{hasChild}.\mathsf{Person}$, since a mother is a parent, and a parent has a child who is a person.
4. $\mathcal{K} \not\models \neg\mathsf{Parent}(\mathsf{tom})$.
   Take the domain $\{m, t, c\}$ with $\mathsf{hasChild} = \{(m, t), (t, c)\}$, $\mathsf{Person} = \{m, t, c\}$, $\mathsf{Female} = \mathsf{Mother} = \{m\}$ and $\mathsf{Parent} = \{m, t\}$.
   Both definitions hold, the ABox holds with $\mathsf{mary} = m$ and $\mathsf{tom} = t$, and $t$ is a parent.
5. $\mathcal{K} \not\models \mathsf{Parent}(\mathsf{tom})$.
   Take the domain $\{m, t\}$ with $\mathsf{hasChild} = \{(m, t)\}$, $\mathsf{Person} = \{m, t\}$ and $\mathsf{Female} = \mathsf{Parent} = \mathsf{Mother} = \{m\}$.
   This interpretation satisfies $\mathcal{K}$ and has $t \notin \mathsf{Parent}$.

## Remarks

Steps 4 and 5 show the open world assumption: the knowledge base says nothing about whether Tom has children, so neither answer is entailed.
A database with the same facts would answer "Tom is not a parent", because it reads missing facts as false.
Step 3 is TBox reasoning alone, while steps 1 and 2 are instance checking, which needs both boxes.

## Explanations

### L1 human

The definitions say what a parent and a mother are.
The facts say that Mary is a woman with a child, Tom.
From these, Mary is a mother.
Nothing is said about Tom's children, so the system does not decide whether Tom is a parent.

### L2 human

1. Write the definitions as the TBox and the facts as the ABox.
2. To prove an assertion, show that it holds in every model.
3. To refute an entailment, build one model of the knowledge base in which the assertion fails.

The typical use is ontology-based query answering, where facts are incomplete.
Watch out: an assertion that is not entailed is not thereby false, so check the negation separately.
