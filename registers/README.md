# Registers

The registers record the decisions about tags that the node files cannot record. Spec 06.4 in tamnd/math2-agent has the design.

Each register is a plain text file with one record on each line. A record has fields with one space between them. A field does not contain a space. A line that starts with `#` is a comment. The first line of each register is a comment that names the fields. A blank line is not a record.

Do not change or remove a record. Add a new record. Thus `git log -p` on a register is the full history of the decisions in it.

## tags.reg

One record for each tag that exists or existed. The records are sorted by tag. Do not edit this file. The mint workflow adds the records (CONTRIBUTING.md).

| Field | Value |
|---|---|
| tag | the tag, for example `7K3QX2` |
| commit | the commit of the pull request at which the tag was minted |
| kind | the kind of the node when the tag was minted |

Example: `7K3QX2 3d3c42e5aac5ba805825da76410c181273ba90b1 statement`

Rule T05: each node file in `nodes/` has a record. Each record has a node file, or a record in `retired.reg`.

## aliases.reg

One record for each assignment of an alias to a tag. An alias can move to a different tag. When it moves, write the end date in the `until` field of the old record and add a new record.

| Field | Value |
|---|---|
| alias | words of lowercase letters and digits with a hyphen between them, for example `compact-space` |
| tag | the tag that the alias names |
| from | the first date of the assignment, for example `2026-11-02` |
| until | the last date of the assignment, or `-` while the assignment is in effect |

Example: `compact-space 7K3QX2 2026-11-02 -`

`m2 fmt` changes an alias in a link to the tag that the alias names now (rule T04).

## retired.reg

One record for each tag that is retired. A retired tag does not name a node. It is not used again.

| Field | Value |
|---|---|
| tag | the retired tag |
| date | the date of the retirement |
| reason | `duplicate`, `split`, `merged` or `error` |
| successors | the tags that replace the retired tag, with a comma between them, or `-` if there is no successor |

Example: `1H8D2C 2027-01-15 duplicate 7K3QX2`

## bindings.reg

One record for each change of a formal binding. The record answers the question "which Mathlib name did this node have at a given date".

| Field | Value |
|---|---|
| tag | the tag of the node |
| system | the formal system, for example `lean4` |
| old | the old declaration, or `-` for a new binding |
| new | the new declaration, or `-` when the binding is removed |
| cause | `bind`, `rename`, `refactor` or `rebind` |
| mathlib | the Mathlib commit at which the change occurs |
| author | the person who made the change, as `orcid:` and an ORCID iD or `github:` and a GitHub login, or `-` |

Example: `7K3QX2 lean4 Subgroup.card_subgroup_dvd_card Subgroup.card_dvd_of_le rename 0123456789abcdef0123456789abcdef01234567 github:octocat`

The author of a binding is the author of its `bind` or `rebind` record. A `rename` or a `refactor` keeps the author. A reviewer cannot review a binding that the reviewer wrote (rule V02).

## reviewers.reg

One record for each reviewer. Rule V02 uses it to check that two fidelity reviews are independent.

| Field | Value |
|---|---|
| reviewer | `orcid:` and an ORCID iD, or `github:` and a GitHub login |
| first | the date of the first review |
| areas | the MSC2020 codes of the areas, with a comma between them |
| affiliations | the ROR ids of the affiliations of the reviewer, for example `ror:03vek6s52`, with a comma between them, or `-` |

Example: `github:octocat 2026-12-01 20D,20E ror:03vek6s52`

A review counts for the fidelity level only when its reviewer has a record. F3 needs two reviewers with no shared affiliation.

## samples.reg

One record for each binding in the monthly re-review sample of spec 10.8. `m2 review sample -write` adds the records of a month. Do not edit this file by hand. A later record of the same binding in the same month gives the re-review to a different reviewer, for example when the first reviewer of the sample cannot do it.

| Field | Value |
|---|---|
| month | the month of the sample, as `YYYY-MM` |
| seed | the seed of the draw. The same seed and the same build give the same sample. |
| tag | the tag of the node |
| decl | the declaration of the binding |
| level | `F2` or `F3`, the level of the binding at the time of the draw |
| first | the ids of the reviews of the binding at the time of the draw, with a comma between them, or `-` |
| reviewer | the reviewer who does the re-review, from `reviewers.reg`, or `-` when no registered reviewer can do it |

Example: `2026-11 3f9a01c2b7d4e588 7K3QX2 Subgroup.card_subgroup_dvd_card F2 r-7K3QX2-01 github:octocat`

The reviewer of a sample did not write the binding and has no review in `first`. `m2 review measure` finds the re-review of each record and gives the disagreement of each level and area.

## crosswalk.reg

One record for each decision of a person on a crosswalk edge. `m2 align accept`, `m2 align reject` and `m2 align confirm` add the records. Do not edit this file by hand. The records are in the order of their tags, and the records of one tag are in the order of the decisions. A later record on the same edge is the newer decision.

| Field | Value |
|---|---|
| tag | the tag of the node |
| edge | `same_as`, `close_to`, `aligned` or `duplicate` |
| system | the external system, for example `wikidata`, or `math2` for a duplicate |
| id | the id in the system, the locator of a paper, or the tag of the other node of a duplicate. The id is escaped as a part of a URL path, thus it has no space. |
| decision | `accepted`, `rejected` or `confirmed` |
| person | `orcid:` and an ORCID iD, or `github:` and a GitHub login. An agent cannot decide. |
| date | the date of the decision |
| record | the hash of the external record at the time of the decision, or `-` when the tree had no records of the system |

Example: `3C53TD same_as wikidata Q505798 accepted github:octocat 2026-10-26 blake3:0123456789abcdef`

The aligner does not propose an edge again after a person rejected it. Rule A02 reports a `same_as` value that an agent wrote and that no person accepted or confirmed in 90 days. Rule A03 reports a value whose record is gone or has a different hash after the decision.
